## 2026-09-14 仕様の査読（対象: `docs/spec.md` 初版「仕様（未実装）」・`docs/draft/` 3点）

### まとめ

- **必須 0件・推奨 24件**（画面の外の注記 2件は数えない）
- 必須を0件にした理由: どの画面も押す的（56px 以上）・戻り道（もどる）・読み上げの経路が書かれていて、「書いてあるとおりに作ると子どもが使えない」所は見つからなかった。ただし次の推奨は、作り方しだいで**子どもがひとりで抜け出せなくなる**ので先に見てほしい:
  - **R1** ピンチで拡大されたまま戻れない
  - **R2** 声の有無を早合点して、声の出る iPad でも黙る
  - **R7** 縦にされると見切れる
  - **R13** 「もどる」が効かない・アプリの外へ出る
  - **R24** 正しくなぞっても はなまるにならない恐れ（測っていない）

### 全体・画面の外（spec §1・§8）

**必須**: なし

**推奨**

- **R1 〔迷う〕ピンチで拡大されたまま戻れない**
  - §8 で止めているのは長押しとダブルタップだけ。iOS の Safari は iOS 10 以降 viewport の `user-scalable=no` を無視するので、何もしなければ2本指で広げられる。下の子は拡大されたまま戻せないし、2人で同時に触ると起きやすい。
  - 案: §8 に「**ピンチ拡大もさせない**」を足す（方法は実装で決める。例: Safari の `gesturestart` を止める）。§11 に「2本指で広げても拡大しない」。
- **R2 〔迷う〕声の有無を早合点して黙る**
  - §8「日本語の音声が無い端末では無音で動かす」。ところが Safari の `speechSynthesis.getVoices()` は最初に空で返ることがある（版による）。起動時に空だから「声が無い」と決めてしまうと、声の出る iPad でもずっと無音になる。下の子が使う画面2の役目が果たせないうえ、失敗が無言になる。
  - 案: §8 に「**声の一覧で speak を止めない**（`lang='ja-JP'` を付けて毎回呼ぶ。声が無い端末でも害はない）。おとな向けの一言は、声の一覧がそろった後で日本語が無いと分かったときだけ出す」を足す。
- **R3 〔迷う〕声が出ないとき、押した手応えが無い**
  - 音量0・消音・読み上げが詰まったとき、画面2・3のカードや大きな字は押しても見た目が変わらない（押したとき縮むのは §3 の表のマスだけ）。子どもは「こわれた」と思って連打する。
  - 案: 押したら**見た目でも返す**（カードが少し縮む／♪ が0.3秒光る）ことを §4（大きな字）・§5・§6 に足す。
- **R4 〔迷う〕連打のあと・開き直したあとに声が止まったままになる恐れ**
  - iOS の読み上げは、`cancel()` の直後の `speak()` や、裏に回ってから戻ったあとに鳴らなくなることがある（端末・版で差がある）。
  - 案: §11 に「カードを続けて速く押しても声が出る」「ホームに戻って開き直しても声が出る」「**ホーム画面のアイコンから開いたときも声が出る**」を足す。
- **R5 〔迷う〕1字の読み違えに備えが無い**
  - §11 は「は・へ・を を正しく読むか」を**確かめる**だけで、読み違えたときにどうするかが無い。下の子は声で覚えるので、例えば「は」が「わ」と読まれると違う音で覚えてしまう。
  - 案: 読み違える字が出たときの代わりを先に §8 に書いておく（例: その字だけカタカナで読ませる／「は、はなの は」のように単語を添える）。§11 の対象に「**ん**」も足す（1字だけで読ませると聞き取りにくい音になりやすい）。
- **R6 〔迷う〕開き方しだいで はなまるが「消える」**
  - (a) iOS では、ホーム画面のアイコンから開いたときと Safari から開いたときで、端末の記録（`localStorage`）が**別々**になる。開き方によって ◎ が出たり出なかったりする。
  - (b) Safari から開く使い方だと、しばらく（7日ほど）開かないでいる間に、サイトが残した記録が Safari の追跡防止で消されることがある（ホーム画面から開く場合は、そのアプリを使った日で数える）。
  - 子どもには「はなまる なくなった」と見える。
  - 案: §1 か §8 で「**開くのはホーム画面のアイコンだけ**」と決め、表の下のおとな向け説明にも書く。§11 に「ホーム画面から開いて、閉じて開き直しても ◎ が残る」。
- **R7 〔迷う〕〔やらない〕縦にされると見切れる**
  - 下の子は iPad を回す。縦（幅 768px）だと、10列の表（約950px）も、画面4（左の列＋枠＋ボタン列）も入らず、端の列や「できた！」が見切れる恐れがある。Safari のページからは向きを固定できない（固定は端末の画面の向きのロックだけ）。
  - 案: §9 に「**縦向きの配置は作らない**」と書く。縦のときは表の代わりに「よこに してね」の**絵**（横に回す iPad の絵）だけを出す。おとな向け説明に「画面の向きのロック」を書く。
- **R8 〔迷う〕失敗の一言が子どもに読めない**
  - 「うまく ひらけませんでした。おうちの ひとに いってね」は字だけ。
  - 案: 同じ所に絵（こまった顔など）を添え、見れば大人を呼べるようにする。
- **R9 〔やらない〕アプリの外へ出る操作**
  - 下の子は、画面下からのスワイプ（ホーム）、上からの引き下ろし、Safari のタブや URL バーに触って外へ出てしまう。ページの側では止められない。
  - 案: §9 に「ページの外へ出る操作は止めない（止められない）」と書く。おとな向け説明に「**アクセスガイド**（設定 › アクセシビリティ）を使うと Safari の外へ出ない」を書く。

### 画面1 ひょう（spec §3）

**必須**: なし

**推奨**

- **R10 〔迷う〕表の下へスクロールすると表が切れる**
  - 表の下におとな向けの文が続くので、子どもが上下になでると表が半分切れ、戻し方が分からない。もじページから戻ったときにスクロールがどこにあるかも §3・§4 に書かれていない。
  - 案: 「表に戻ったときは一番上」を §4 に書く。できれば、おとな向けの文は表の画面から外す（例: 隅の小さな「？」から開く別の画面。子どもが押しても害がないように、文だけの画面にする）。

### もじページの共通枠（spec §4）

**必須**: なし

**推奨**

- **R11 〔迷う〕タブと「もどる」が文字だけ**
  - 「え と ことば」「ことば」「なぞる」「‹ もどる」は、ひらがなを習う前の子には読めない。▶ で**どれが選ばれているか**は分かるが、**どれが何か**は分からない（CLAUDE.md §4「形か音も添える」）。
  - 案: 各タブに絵を添える（え と ことば＝小さな額の絵、ことば＝「あ」の札、なぞる＝指の絵）。もどる には表の小さな絵を添える。
- **R12 〔迷う〕大きな字を押せると分からない**
  - 160px の字は飾りに見える。この字を押すのが、その字の音を聞く唯一の方法。
  - 案: 字の角に、画面2のカードと同じ **♪ 印**を付ける。
- **R13 〔押せない〕「もどる」が効かない・アプリの外へ出る恐れ**
  - 字のページ（`#ka`）を開いた状態でホーム画面に追加すると、アイコンがその字のページから始まる。このとき「もどる」を `history.back()` で作っていると、ホーム画面から開いた場合は戻る先が無くて何も起きない（Safari の戻るボタンもスワイプも無いので、子どもは表に戻れない）。Safari から開いた場合は、前のページ（アプリの外）へ出てしまう。
  - 案: §4 に「**もどる は常に画面1を出す**（履歴を1つ戻すのではない）」と書く。おとな向け説明に「ホーム画面に追加するのは表を開いているとき」と書く。
### 画面2 え と ことば（spec §5）

**必須**: なし

**推奨**

- **R14 〔迷う〕〔押せない〕「を」のページに押せそうな物が無い**
  - 説明の文と例文だけで、絵もカードも無い。例文が押せることが見て分からない（草案の例文は、押しても何も起きない太字だった）。§5 には例文の大きさも書かれていない。
  - 案: 例文「ほんを よむ」を、ほかと同じ**カードの形**にする（ほん の絵・♪ 印・高さ 64px 以上）。絵 `hon` はもうある。
- **R15 〔迷う〕を・ん の説明が読めず、押しても鳴らない**
  - 説明文は字だけ。上の子は「を」「ん」がどういう字なのか分からないままになる。画面3も同じ。
  - 案: 説明文も**押すと読み上げる**（♪ 印を付ける）。§5・§6 に足す。
- **R16 〔やらない〕「ちょうちょ」は拗音**
  - §1・§9 で拗音は入れないとしたが、ち の単語「ちょうちょ」は ち を「ちょ」と読む。§2 の「全部強調」で ち が2つ色付くのに、声は「ちょう・ちょ」で、ち の音と合わない。
  - 案: ち の語を拗音の無い語に替える（例: ちくわ）。§9「単語の入れ替えはしない」の例外にする。絵を1点描き足し、`chouchou` を消す（tests の「使われない絵が無い」に合わせる）。
- **R17 〔迷う〕2〜4歳に分かりにくい語**
  - るすばん（ことがらの語で、絵では表しにくい）、るびー（見たことが少ない）。へや・よる も、絵を見て分かるか怪しい。
  - 案: §9 のとおり後で直すなら、§11 に「**るすばん・るびー・へや・よる を子どもが絵で分かるか**」と語を名指しで入れておく。

### 画面4 なぞる（spec §7）

**必須**: なし

**推奨**

- **R18 〔迷う〕「できた！」「けす」が字だけ**
  - 上の子はまだ読めない。色（朱色）で区別が付いても、どちらが何かは押してみるまで分からない。
  - 案: できた！ に**はなまるの絵**、けす に**けしごむの絵**を添える（`keshigomu` はもうある）。
- **R19 〔迷う〕「けす」と「できた！」が隣り合う**
  - 縦に 64px で並べると、できた！ を狙って けす に当たりやすい。描いた線が判定の前に消える。
  - 案: 2つの間に判定のことばを挟む（上から できた！ → 判定のことば → けす）か、32px 以上あける。けす は できた！ より小さく、目立たなくする。
- **R20 〔迷う〕最初の案内が声で出ない**
  - 「しろい せんの うえを ゆびで なぞってね」は字だけ。なぞる を開いた子は何をすればよいか分からない。
  - 案: **なぞるタブを押したとき**、同じことばを声でも言う（押したときに鳴るので CLAUDE.md §4 の範囲）。
- **R21 〔迷う〕〔やらない〕2本目の指で線が飛ぶ**
  - 手のひらをついたり2人で同時に触ったりすると、Pointer Events は指ごとに届く。前の点とつながって長い直線が走り、判定もずれる。
  - 案: §7 に「**最初に触れた1本の指（pointerId）だけで描き、ほかの指は無視する**」と書く。§9 に「2人同時に描く」を足す。
- **R22 〔迷う〕なぞった線が地の色に沈む**
  - 線は濃い色（草案 `#25313A`）、地は行の濃色。§8 は行の濃色を「白い字との比 3:1 以上」まで暗くするので、暗くしすぎた行では濃い線との差が小さくなり、どこをなぞったか見えにくい（`#25313A` と比 3:1 を保つには、行の濃色の明るさ（相対輝度）が 0.19 以上要る）。
  - 案: §8 の色の条件に「**なぞった線と行の濃色の比も 3:1 以上**」を足す（線をもっと暗くする、白いふちを付ける など）。
- **R23 〔押せない〕なぞり枠の大きさが幅を見ていない**
  - §7 は「1辺は使える高さに合わせて 480〜560px」。1024×768 では高さから決めると 560px になる。幅のほうは 1024 − 左の列 280 − 左右の余白 32 − すき間2つ 48 − ボタン列 約180 ≒ **484px** が上限。高さだけで決めるとボタン列が細くなり、「できた！」が押しにくくなるか、はみ出す。
  - 案: 「1辺 ＝ **高さと幅（左の列とボタン列を引いた残り）の小さい方**、480〜560px」と書く。
- **R24 〔迷う〕判定の数値が、いちばん太い字形で届くか確かめていない**
  - 線の太さは枠の5%（600 中 30）、はなまるは「なぞれた割合 55% 以上」。字形はいちばん太い 900 なので、字の線の太さが線幅の2倍近くあると、真ん中を正確に1回なぞっても 55% に届かない恐れがある。そうなると上の子は、正しくなぞっても「もうすこし！」と言われ続ける。
  - ここではフォントが手元に無いので**測っていない**（取得は §10-4 で許可待ち）。草案の元のページで取れていたなら問題ない。
  - 案: `tests/` の機械チェックに「字の中心線を線幅で描いたときのなぞれた割合が、46字すべてで 55% を十分こえる（例: 70% 以上）」を足す。届かない字があれば、線幅か閾値を直す。
